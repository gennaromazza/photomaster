1. Estrazione della Logica Comune di Calcolo Totali e Gestione Sconti
Creiamo un helper (ad es. in src/lib/moduleCalculations.ts) che centralizza il calcolo degli importi per un item. In questo modo sia il FixedModule che il VariableModule possono usarlo.

ts
Copia
// src/lib/moduleCalculations.ts
import { QuoteModuleItemData } from "@/components/module-selector";

export function calculateItemTotals(item: QuoteModuleItemData): QuoteModuleItemData {
  const qty = item.quantity || 1;
  const unitPrice = item.unitPrice || 0;
  if (!item.hasDiscount) {
    return { ...item, total: qty * unitPrice, discountedPrice: undefined };
  } else {
    const discountType = item.discountType || 'percentage';
    const discountValue = item.discountValue || 0;
    if (discountType === 'percentage') {
      const discountedPrice = unitPrice * (1 - discountValue / 100);
      return { ...item, discountedPrice, total: qty * discountedPrice };
    } else { // fixed
      const discountedPrice = Math.max(0, unitPrice - discountValue);
      return { ...item, discountedPrice, total: qty * discountedPrice };
    }
  }
}
Successivamente, all’interno dei moduli, sostituire le sezioni di “ricalcolo totale” con una chiamata a questa funzione.

2. Creazione di un Custom Hook per il Caricamento dei Dati
Per evitare duplicazioni, creiamo un hook comune per recuperare i servizi, prodotti e pacchetti (ad es. useAvailableItems):

ts
Copia
// src/hooks/useAvailableItems.ts
import { useEffect, useState } from "react";

export interface AvailableItems {
  services: any[];
  products: any[];
  bundles: any[];
}

export function useAvailableItems() {
  const [items, setItems] = useState<AvailableItems>({
    services: [],
    products: [],
    bundles: [],
  });
  const [error, setError] = useState<string | null>(null);

  useEffect(() => {
    const fetchData = async () => {
      try {
        const res1 = await fetch("/api/services");
        if (res1.ok) {
          const allItems = await res1.json();
          const services = allItems.filter((item: any) => item.type === 'service');
          const products = allItems.filter((item: any) => item.type === 'product');
          // Imposta nel contesto anche servizi e prodotti
          setItems(prev => ({ ...prev, services, products }));
        }
        const res2 = await fetch("/api/service-bundles");
        if (res2.ok) {
          const bundles = await res2.json();
          setItems(prev => ({ ...prev, bundles }));
        }
      } catch (error) {
        setError("Errore nel caricamento dei dati");
      }
    };

    fetchData();
  }, []);

  return { ...items, error };
}
In FixedModule e VariableModule, puoi usare:

ts
Copia

3. Revisione di handleItemChange per il Reset dei Campi
Modifichiamo la funzione in modo che se il valore passato è “falsy” (ad es. il campo viene deselezionato) resetti anche i campi correlati.

ts

// Esempio semplificato per un ramo. All’interno di handleItemChange:

}
Applica lo stesso schema per productId e bundleId.

4. Gestione della Selezione in PublicVariableModule Basata su ID
Modifica la gestione delle selezioni in PublicVariableModule per usare un array di ID invece degli indici. Esempio:

tsx
Copia
// public-variable-module.tsx
import React, { useEffect, useState } from "react";
// importazioni ...

export function PublicVariableModule({ module, onSelectionChange }: PublicVariableModuleProps) {
  if (!module || !module.items) {
    console.error("Module o module.items non definito:", module);
    return (
      // UI per modulo non disponibile
    );
  }

  // Usa array di id selezionati anziché indici
  const [selectedIds, setSelectedIds] = useState<number[]>([]);

  useEffect(() => {
    // Inizializza con gli id degli item obbligatori, se esiste la proprietà minSelectCount
    const initialSelected: number[] = module.items
      .filter((item: any) => item.minSelectCount && item.minSelectCount > 0)
      .map((item: any) => item.id);
    setSelectedIds(initialSelected);
  }, [module.items]);

  useEffect(() => {
    let sum = 0;
    selectedIds.forEach(id => {
      const item = module.items.find((item: any) => item.id === id);
      if (item) {
        sum += item.total || 0;
      }
    });
    // Aggiorna il totale e invoca la callback:
    if (onSelectionChange) {
      onSelectionChange(module.id, selectedIds);
    }
  }, [selectedIds, module, onSelectionChange]);

  const handleItemSelect = (itemId: number, checked: boolean) => {
    const item = module.items.find((item: any) => item.id === itemId);
    if (!item) return;
    if (checked) {
      setSelectedIds(prev => [...prev, itemId]);
    } else {
      // Non consente la deselezione se obbligatorio
      if (item.minSelectCount && item.minSelectCount > 0) return;
      setSelectedIds(prev => prev.filter(id => id !== itemId));
    }
  };

  // Esempio di render dell'item, controlla se l'item è selezionato confrontando il suo id:
  return (
    <div>
      {module.items.map((item: any) => {
        const isSelected = selectedIds.includes(item.id);
        return (
          <div key={item.id}>
            <input 
              type="checkbox"
              checked={isSelected}
              onChange={(e) => handleItemSelect(item.id, e.target.checked)}
            />
            <span>{item.serviceName || item.productName || item.bundleName}</span>
            <span>{/* Visualizza totale per item */}</span>
          </div>
        );
      })}
    </div>
  );
}
5. Gestione del Share Token nei Moduli Variabili
Nel VariableModule assicuriamoci che, al momento del salvataggio, se non esiste un token, viene generato (oppure richiediamo al backend di generarlo e aggiornare il form).

ts
Copia
// Esempio: nel useEffect del VariableModule
useEffect(() => {
  if (!module?.shareToken) {
    // Opzione 1: Generare un token lato client (se la logica lo permette)
    const token = generateRandomToken(); // Funzione helper da definire
    setFormData(prev => ({ ...prev, shareToken: token }));
    setShareUrl(`${window.location.origin}/quotes/modules/${token}`);
  } else {
    setShareUrl(`${window.location.origin}/quotes/modules/${module.shareToken}`);
  }
}, [module]);

// Funzione helper per generare un token semplice
function generateRandomToken(length = 16) {
  return Math.random().toString(36).slice(2, 2 + length);
}
Assicurati che il backend, se gestito diversamente, sincronizzi il token generato (oppure richiedi un’API per generarlo).

8. Creazione di un Componente per Immagini con Fallback
Per gestire le immagini in maniera dichiarativa e riutilizzabile, crea un componente ImageWithFallback:

tsx
Copia
// src/components/ImageWithFallback.tsx
import React, { useState } from "react";

interface ImageWithFallbackProps extends React.ImgHTMLAttributes<HTMLImageElement> {
  fallbackSrc: string;
}

export function ImageWithFallback({ fallbackSrc, src, alt, ...props }: ImageWithFallbackProps) {
  const [imgSrc, setImgSrc] = useState(src);
  const handleError = () => setImgSrc(fallbackSrc);
  return (
    <img src={imgSrc} alt={alt} onError={handleError} {...props} />
  );
}
Utilizza questo componente in PublicFixedModule e PublicVariableModule al posto della gestione manuale dell’errore.

Conclusioni
La soluzione definitiva prevede:

Centralizzazione della logica di calcolo tramite helper (e possibilmente custom hook) per evitare duplicazioni.

Creazione di un hook unificato per il caricamento dei servizi, prodotti e pacchetti.

Modifica della funzione di aggiornamento dei campi (handleItemChange) per gestire correttamente il reset in caso di deselezione.

Utilizzo degli ID per la selezione nei moduli variabili per una gestione robusta e indipendente dagli indici.

Implementazione della generazione del shareToken al momento della creazione del modulo variabile.

Aggiornamento dello stato iniziale dei moduli variabili a “pending_selection” e adeguamento delle interfacce TypeScript.

Creazione di un componente ImageWithFallback per una gestione più pulita dei problemi di caricamento immagine.

Questa soluzione integrata rende il codice più manutenibile, previene incoerenze di stato e garantisce una migliore esperienza utente sia durante la configurazione che nella visualizzazione finale del preventivo.
