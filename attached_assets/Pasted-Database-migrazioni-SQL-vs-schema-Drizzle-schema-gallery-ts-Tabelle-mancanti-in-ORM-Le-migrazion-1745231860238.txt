Database (migrazioni SQL) vs schema Drizzle (schema_gallery.ts)
Tabelle mancanti in ORM
Le migrazioni SQL creano anche le tabelle gallery_chapters e photos (con indici su gallery_id e chapter_id), ma non esiste alcuna definizione Drizzle per queste tabelle nel file schema_gallery.ts. Di conseguenza non è possibile usarle con l’ORM e non esistono le relative relazioni/relations() in codice.

Allineamento galleries
La definizione Drizzle di galleries corrisponde esattamente ai campi e ai default impostati nella migrazione SQL:


Colonna	SQL migration	Drizzle schema
is_public	BOOLEAN NOT NULL DEFAULT FALSE	boolean("is_public").default(false).notNull()
slug	TEXT NOT NULL UNIQUE	text("slug").notNull().unique()
…	…	…
(ho controllato tutti i campi fino a notification_email_template e coincidono).

2. Drizzle schema vs logica server / Zod
Campo userId mancante
Nel TypeScript server (e in GalleryItem client) compare userId, ma in schema_gallery.ts non esiste la colonna user_id.
❌ GalleryItem.userId: number
✔️ Tabella SQL e Drizzle definiscono solo event_id, non user_id.

Campi non inseribili
Lo insertGallerySchema include tutti i campi principali, ma non espone (per scelta?) alcuni campi con default in tabella, ad esempio:

studio

viewCount

showInClient

eventuali campi di social/SEO.
Se serve permettere all’utente di configurarli al momento della creazione, andrebbero aggiunti.

3. Client‑side TypeScript (client/src/types/gallery.ts) vs DB
Campi mancanti in GalleryItem

shortDescription (DB short_description)

headerImage

expiryDate

layout, theme

downloadEnabled, selectionEnabled

clientMessage, showInClient

metaData, studio, watermarkEnabled

Tutti i campi di social media, tagging prompt e notifiche

Campi extra in GalleryItem

userId (non esiste in DB)

likeCount, commentCount (vanno calcolati da tabelle collegate, non sono colonne di photos)

Incoerenze su photos

DB: colonne path, thumbnail_path, medium_path, large_path, webp_path, uploaded_at

TS Photo: proprietà url (→ path?), thumbnailUrl, largeUrl, webpUrl manca mediumUrl

TS Photo ha createdAt e updatedAt, ma DB definisce solo uploaded_at (manca updated_at)

4. Componenti React & form

GalleryCard e GalleryGrid usano il tipo GalleryItem, che non include tutti i campi di presentazione definiti in tabella: ad esempio se in futuro volessimo mostrare la data di scadenza (expiryDate) o il tema (theme), non sono contemplati.

5. Raccomandazioni
Definire in Drizzle anche gallery_chapters e photos (e relative relazioni).

Allineare gli schemi Drizzle alle migrazioni: aggiungere/rimuovere campi dove serve (es. user_id).

Estendere i tipi TS (GalleryItem, Photo, ecc.) per coprire tutti i campi di DB, oppure creare tipi dedicati “di ritorno” con subset di campi.

Mappare correttamente il nome dei campi tra server e client (medium_path → mediumUrl, uploaded_at → createdAt, ecc.).

Aggiungere updated_at in photos se serve tenere traccia delle modifiche.

Verificare i form: assicurarsi che i campi di gallery-form.tsx corrispondano allo insertGallerySchema.

Con queste correzioni il comparto gallerie risulterà coerente end‑to‑end, da database a UI.
