Titolo: Implementazione Dashboard Pubblica Collaboratore

Obiettivo
Fornire a ciascun collaboratore un’area riservata, accessibile via link unico (token-based), in sola lettura, dove possa consultare:
- Elenco eventi assegnati con data e ruolo
- Stato pagamenti: elenco transazioni, riepilogo acconti, saldi e saldo residuo
- Coda montaggi: stato, priorità, date di consegna previste

Tutto deve rispettare i criteri di **modularità**, **semplicità** e **responsive design** già in uso nel progetto.

---

1. Struttura file
- `client/src/pages/collaboratori/[id]/dashboard-public.tsx`
- `client/src/modules/collaboratori/components/DashboardPublic/`
  - `DashboardPublic.tsx` (componente container)
  - `EventListPublic.tsx`
  - `PaymentSummaryPublic.tsx`
  - `PaymentListPublic.tsx`
  - `MontageQueuePublic.tsx`

2. Autenticazione e sicurezza
- Generazione di `tokenCollaboratore`:
  - Durante l’assegnazione del primo evento o su richiesta, backend genera un token JWT firmato (`userId`, `expiresIn=30d`)
  - Salvare token in DB (campo `dashboardToken` in tabella `collaboratori`)
- Middleware API:
  - Verifica `req.query.tokenCollaboratore` o header `Authorization: Bearer <token>`
  - Decode JWT e controlla corrispondenza con `collaboratori.id`
  - Se non valido → 401/403

3. API: `/api/collaboratori/:id/dashboard-public`
- Metodo: GET
- Parametri: `req.params.id`, `req.query.tokenCollaboratore`
- Query DB (Drizzle ORM):
  ```ts
  const collaboratore = await db.select().from(collaboratori)
    .where(eq(collaboratori.id, id))
    .where(eq(collaboratori.dashboardToken, token))
    .limit(1);
  const eventi = await db.select().from(eventiCollaboratori)
    .where(eq(eventiCollaboratori.collaboratoreId, id));
  const pagamenti = await db.select().from(pagamentiCollaboratori)
    .where(eq(pagamentiCollaboratori.collaboratoreId, id));
  const montaggi = await db.select().from(montaggi)
    .where(eq(montaggi.collaboratoreId, id));
  ```
- Risposta JSON:
  ```json
  {
    "collaboratore": { "id","nome","ruolo" },
    "eventi": [ { "eventoId","eventoNome","dataAssegnazione","ruolo" } ],
    "pagamenti": [ { "tipo","importo","dataPagamento" } ],
    "montaggi": [ { "eventoId","eventoNome","stato","priorita","dataConsegnaPrevista" } ]
  }
  ```

4. Hook front-end
- `useDashboardPublic(id: string, token: string)`
  ```ts
  const { data, error } = useSWR(
    () => token ? `/api/collaboratori/${id}/dashboard-public?token=${token}` : null,
    fetcher
  );
  ```

5. Componente `DashboardPublic.tsx`
- Header:
  - “Ciao, {collaboratore.nome}”
  - Possibilità di copiare link di accesso
- Sezione Eventi:
  - `EventListPublic`: tabella con colonne “Data”, “Evento”, “Ruolo”
- Sezione Pagamenti:
  - `PaymentSummaryPublic`: calcola `totalAcconti`, `totalSaldi`, `saldoResiduo`
  - `PaymentListPublic`: elenco con “Data”, “Tipo”, “Importo”
- Sezione Montaggi:
  - `MontageQueuePublic`: griglia con card montaggio, badge stato, priorità, data consegna

6. Styling & Responsività
- Utilizzare classi Tailwind esistenti:
  - Mobile: sezione in colonna (`space-y-6`)
  - Desktop: grid a 2 colonne (`md:grid-cols-2`)
- Card modulari con `rounded-2xl`, `shadow-sm`, `p-4`

7. Accessibilità
- `aria-live="polite"` sui riepiloghi numerici
- Table headers (`<th scope="col">`)
- Contrasto WCAG per badge di stato

8. Tests
- **API**: Postman/Insomnia:
  - GET con token valido → 200 + struttura JSON  
  - GET con token errato/mancante → 401  
- **Unit** (Jest + React Testing Library):
  - `useDashboardPublic` test per dati mock  
  - Rendering fallback (spinner) e errore  
- **E2E** (Playwright):
  - Accesso via URL con token → verifica presenza dati
  - Copia del link → nuova tab carica dashboard corretta
