Titolo: Implementazione PagamentoCollaboratoreList con riepilogo importi e inserimento pagamenti

Obiettivo: Realizzare un componente React che mostri lo storico dei pagamenti di un collaboratore, con un riepilogo acconti e saldo residuo, e permetta di registrare nuovi pagamenti (acconto/saldo) tramite un form in modal. UI/UX deve rispettare gli stessi token Tailwind, breakpoints e palette, con design mobile-first.

1. Posizione file
client/src/modules/collaboratori/components/PagamentoCollaboratoreList.tsx

2. Hook dati
Riusa useCollaboratore(id) per ottenere l’array pagamenti.

Per il POST, usa SWR mutation o fetcher.post('/api/collaboratori/${id}/pagamenti', {...}).

3. Layout & Tailwind
Header della card: titolo “Pagamenti”, sotto titoli “Acconti”, “Saldo residuo” calcolato dinamicamente (totalAcconti = sum(importo where tipo endsWith '_acconto'), totalSaldo = sum(importo where tipo endsWith '_saldo')).

Lista: tabella con colonne:

Data pagamento (DD/MM/YYYY)

Tipo (acconto, saldo, montaggio_acconto, montaggio_saldo)

Importo (formattato in euro)

Pulsante WhatsApp (icona) per ritrasmettere conferma via link wa.me

4. Modal “Registra Pagamento”
Trigger: bottone “+ Nuovo Pagamento” nel header.

Form (React Hook Form + Zod):

ts
Copia
Modifica
const schema = z.object({
  eventoId: z.string().uuid(),
  tipo: z.enum(['acconto','saldo','montaggio_acconto','montaggio_saldo']),
  importo: z.number().positive('Deve essere > 0'),
  dataPagamento: z.date().max(new Date(), 'Non può essere futura'),
});
Campi:

Select evento (dropdown da /api/collaboratori/${id}/eventi)

Select tipo pagamento

Input number per importo

Datepicker per dataPagamento

Azioni:

onSubmit → POST /api/collaboratori/${id}/pagamenti

Al successo:

chiudi modal

rinfresca SWR key di useCollaboratore(id)

toast “Pagamento registrato”

Al fallimento: toast con errore server.

5. WhatsApp Link
Ogni riga in lista include:

6. Accessibilità & Responsività
Modal full-screen su viewport <640px, box centrata su ≥640px.

Focus trap, aria-labelledby, aria-describedby su modal.

Etichette associate a tutti i campi.

7. Test
Unit test (RTL):

Rendering lista con vari tipi pagamento

Apertura/chiusura modal

Validazione Zod (importo zero, data futura)

E2E (Playwright):

Apri dashboard collaboratore → seleziona tab Pagamenti → clicca “+ Nuovo Pagamento” → compila form → invia → verifica riga in lista e riepilogo aggiornato.
