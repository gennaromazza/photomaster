Verifica Correlazioni DB e Data Retrieval modulo “Collaboratori”

Contesto
A valle dell’implementazione completa del modulo “Collaboratori” (DB, API e UI), vogliamo avviare una fase di verifica focalizzata sulle relazioni di database e sul recupero dati end-to-end, per garantire che ogni livello (schema, controller, endpoint, hook e componenti) restituisca esattamente ciò che serve.

1. Database & Relazioni
Schema & Migrazioni

Controlla che, dopo npm run db:push o la migrazione manuale, esistano le tabelle:

collaboratori

eventi_collaboratori

pagamenti_collaboratori

montaggi

Verifica i tipi di colonna (UUID, Decimal, DateTime) e i default (now(), @updatedAt).

Foreign Keys & Referential Actions

Ogni FK punti al record corretto e abbia ON DELETE CASCADE (o comportamento previsto).

Testa la cancellazione di un collaboratore e verifica che eventi/pagamenti/montaggi correlati vengano rimossi o protetti, come da spec.

Indice & Performance

Assicurati che ci siano indici sulle colonne di join (collaboratoreId, eventoId).

Verifica la presenza di eventuali indici composti (se previsti) per query frequenti.

2. Controller & Query Logic
Controlla i controller in server/controllers/collaboratori-controller.ts:

getDashboard(id)

Recupera collaboratore + eventi + pagamenti + montaggi in una sola query (o col include di Drizzle).

getEventi(id), getPagamenti(id), getMontaggi(id)

Ritorna array di oggetti con solo i campi necessari (no over-fetch).

Le mutazioni (POST, PATCH) usano transazioni per operazioni multiple.

Testa error‐handling sul DB (vincoli unici, FK violati) e il corretto res.status(4xx/5xx) con messaggi.
